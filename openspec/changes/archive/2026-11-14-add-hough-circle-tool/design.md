# Design

## Context

仓库已有两张实拍样图与一版可运行的实现（`hough_circles/`、`scripts/acceptance.py`、`docs/results/`），并有归档变更 `2026-11-14-add-hough-circle-gui`。本次变更用于在评审后重新确认规格与实施范围，apply 阶段先核对现有实现与规格的差异，再补齐缺口。运行环境是 WSL2 + Python 3.12，无 X11 截图工具，不引入 Flask 等 Web 框架。

## Goals / Non-Goals

**Goals:**

- 调参到看到标注结果之间不需要手工改文件或重启进程。
- 验收可在无界面环境用一条命令复现，并产出与界面一致的标注图。
- 现有实现中已满足规格的部分直接复用，避免重复返工。

**Non-Goals:**

- 多用户、鉴权、持久化存储。
- 圆的分类（硬币/盘沿）或自动选参。
- 视频流、批量目录处理。

## Decisions

### 本地 Web 界面，而非桌面窗口

用标准库 `http.server` 提供页面与 JSON 接口，浏览器作为界面。理由：WSL/远程环境无需 X 服务，零额外依赖，便于用浏览器实际操作验收。备选：Tkinter（需要显示服务器）、PyQt（依赖重）。

### 服务端检测与标注，前端只发参数

前端上传图片一次，之后每次调参只发送图片 ID 与参数；服务端返回标注后的 PNG data URL。预览与导出共用 `annotate()` 与 `encode_png()`，保证“所见即所得”。备选：前端 Canvas 画圆，需重复实现绘制逻辑且导出一致性难保证。

### 图片存于内存

以 UUID 索引最近 8 张解码后的图像（LRU），避免每次调参重复上传。进程退出即丢失，符合本地工具定位。

### 参数集合与默认值

暴露 `dp`、`minDist`、`param1`、`param2`、`minRadius`、`maxRadius`、`blur`。默认 `1.2 / 100 / 100 / 45 / 20 / 0 / 5`，其中 `maxRadius = 0` 表示按图像短边的一半自动取值。半径上下限是区分外缘与内部纹理的主要手段。

### 参数校验放在核心层

`dp <= 0`、`maxRadius < minRadius`（且 `maxRadius != 0`）、滤波核非正奇数等非法组合抛 `ValueError`；HTTP 层映射为 400 JSON；界面显示错误但不丢失上一次结果。

### 标注样式

圆周用绿色，线宽随图像尺寸缩放（短边 / 300，最小 2 像素）；圆心为红色实心点；不写编号文字，避免遮挡实拍图细节。导出 PNG，保持原分辨率，文件名 `<原图名>-annotated.png`。

### 验收判据脚本化

`scripts/acceptance.py` 直接调用核心层，按 README 固定参数处理两张样图，断言检出数量与半径区间，输出圆心、半径与边缘支持度，并写入 `docs/results/`。判据不通过时退出码非 0。

| 样图 | dp | minDist | param1 | param2 | minRadius | maxRadius | blur | 期望 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `examples/coins.jpg` | 1.2 | 200 | 100 | 50 | 150 | 210 | 5 | 2 个圆，r 170–190 |
| `examples/cookie-plate.jpg` | 1.2 | 200 | 100 | 40 | 200 | 280 | 5 | 1 个圆，r 235–255 |

### apply 阶段以差异复核为主

现有实现已覆盖规格中的主要行为。实施时逐项核对检测、标注、界面与验收脚本，只修改不满足规格或文档不一致的部分；不为了“重新实现”而重写已验证代码。

## Risks / Trade-offs

- [盘沿对 `param2` 较敏感，取值 40–50 之外会漏检] → README 固定验收参数，脚本使用 40 并打印实际半径；滑杆范围覆盖该区间。
- [大图检测耗时，连续拖动滑杆可能排队] → 前端 250 ms 防抖，服务端按请求并发处理，本地单用户可接受。
- [内存缓存最多 8 张，超大图占用较高] → 限制张数并在淘汰时释放；不做磁盘缓存。
- [“外缘”语义无法仅靠坐标自动证明] → 组合使用半径区间、圆周边缘支持度与人工查看标注图。
- [现有实现与归档记录可能造成重复工作] → 以本变更的 delta 规格为准做差异核对，已满足项不重复开发。

## Migration Plan

不改动样图与既有验收判据。若合并后需回滚，删除本变更新增的规划文件并保留既有实现即可；已归档变更不受影响。
