# Design

## Context

现有实现是单进程本地工具：标准库 `http.server` 提供页面与 JSON 接口，`ImageStore` 在内存中保存最近 8 张解码后的图片，`hough_circles/core.py` 负责参数校验、单张图片检测、标注与 PNG 编解码，`scripts/acceptance.py` 用两张实拍图做固定判据验收。当前请求体上限为 32 MiB，所有处理都在请求线程内完成。

视频功能需要在不改变现有图片接口与验收结果的前提下，增加较大的上传、长时间处理、进度反馈和取消。以下设计只作为交接后的实现依据，本次分支不落地代码。

## Goals / Non-Goals

**Goals:**

- 复用 `HoughParams` 与 `detect()`，保证视频帧和图片使用同一套参数、校验、排序和标注逻辑。
- 处理期间可查询进度、可取消；进程退出后不要求恢复任务。
- 逐帧结果可用 CSV 复核，采样帧可单独预览标注图。
- 不新增 Python 依赖，继续使用 `opencv-python`、`numpy` 和标准库。
- 保持现有 `/api/upload`、`/api/detect`、`/api/export` 与两张图片的验收判据不变。

**Non-Goals:**

- 实时摄像头、RTSP 流、批量目录处理。
- 跨帧目标跟踪、圆身份关联、轨迹平滑。
- 多用户、鉴权、任务持久化、断点续跑。
- 自动调参、按内容自适应帧间隔。
- 首版不导出标注视频；先交付逐帧 CSV 与单帧标注预览。

## Decisions

### 视频解码用 `cv2.VideoCapture`

OpenCV 已随现有依赖安装，自带 FFmpeg 后端即可读取常见 MP4/AVI/MOV，不需要系统安装 `ffmpeg` 命令行。用 `CAP_PROP_FRAME_COUNT`、`CAP_PROP_FPS`、`CAP_PROP_FRAME_WIDTH/HEIGHT` 读取元数据；元数据缺失或为 0 时以实际解码为准，不直接信任容器头。

备选：调用 `ffmpeg`/`ffprobe` 子进程。当前环境没有该命令，且会引入外部依赖，不采用。

### 上传先落临时文件，再创建任务

视频通常超过现有 32 MiB 请求上限。新增 `POST /api/video/upload`，按块读取请求体写入临时文件，默认上限 512 MiB；读取完成后用 `VideoCapture` 校验可解码性并读取元数据。校验通过后创建任务，临时文件随任务生命周期保留，任务淘汰或进程退出时删除。

备选：把整个视频读入内存。大视频会成倍占用内存，不采用；也不把视频塞进现有 `ImageStore`。

### 任务模型：内存中的后台线程

新增 `VideoJob`，字段至少包括：任务 ID、原文件名、临时文件路径、元数据、参数、帧间隔、采样帧总数、已处理帧数、状态（`queued`/`running`/`completed`/`cancelled`/`failed`）、逐帧结果、错误信息和取消事件。每个任务一个 `threading.Thread`，在帧循环边界检查取消事件。

任务表沿用现有 LRU 思路，最多保留 4 个任务；淘汰时删除临时文件。进程退出即丢失任务，符合本地工具定位。锁只保护任务表和进度字段，检测本身在后台线程内串行执行。

### 采样与时间戳

采样帧号为 `0, step, 2*step, ...`，其中 `step` 是正整数帧间隔，默认 5。时间戳按 `time_ms = round(frame_index / fps * 1000)` 计算；`fps` 无效时时间戳留空并在结果中标记。总采样帧数优先用 `ceil(frame_count / step)`，实际解码到文件末尾时以实际处理数为准。

### 接口划分

- `POST /api/video/upload`：流式接收视频，返回视频 ID 与元数据。
- `POST /api/video/start`：接收视频 ID、`HoughParams`、`frameStep`，创建任务并返回任务 ID。
- `GET /api/video/status?id=...`：返回状态、已处理/总采样帧数、进度、错误信息。
- `POST /api/video/cancel`：设置取消事件，返回当前状态。
- `GET /api/video/results?id=...`：返回逐帧结果摘要与每帧圆列表。
- `GET /api/video/frame?id=...&frame=...`：返回指定采样帧的 PNG 标注图。
- `GET /api/video/export?id=...`：仅在 `completed` 时返回 CSV。

现有 `POST /api/detect` 仍只处理图片；视频模式不改变它的请求与响应。

### CSV 结构

用标准库 `csv` 写出 UTF-8 CSV，列固定为 `frame,time_ms,count,circle_index,x,y,r`。每个采样帧至少一行；有检出时按圆序号展开为多行，`count` 在每行重复；无检出时写 `count=0`，其余列留空。文件名使用原视频名加 `-circles.csv`。

### 前端状态机

界面增加模式切换，视频模式复用现有 7 个参数滑杆。状态分为：未选择视频、已选择、处理中、已完成、已取消、失败。处理中每 500 ms 轮询一次状态；切换模式不销毁运行中的任务，切回后继续显示。预览帧通过下拉框选择采样帧，加载 `/api/video/frame` 返回的 PNG。

### 验收看样例来源

优先加入一段不超过 10 秒、体积不超过 5 MiB、许可允许再分发的公开视频，并在 `examples/SOURCES.md` 记录来源与许可。若找不到合适素材，用脚本从现有 `coins.jpg` 与 `cookie-plate.jpg` 生成一段确定性短视频，避免引入新的许可问题。

验收判据在样例确定后写入 README 和 `scripts/acceptance.py`：固定 `frameStep` 与参数，断言采样帧数、CSV 行数、至少一帧检出圆且半径落在给定区间；另测一次取消和一次损坏文件导入。样例缺失时脚本必须非零退出并提示获取方式，不能静默跳过。

## Risks / Trade-offs

- [OpenCV 后端对某些编码不支持] → 导入时用 `VideoCapture.isOpened()` 和首帧解码做双重校验；README 明确支持的容器，错误信息提示转码为 H.264 MP4。
- [长视频处理时间远超请求超时] → 任务异步化，HTTP 请求只负责创建/查询；前端轮询而不是长连接。
- [大文件上传占用磁盘和内存] → 流式写入临时文件，限制 512 MiB，任务淘汰时删除；不把整个文件读入内存。
- [后台线程与进度字段竞争] → 用锁保护任务表和计数；检测结果只在任务线程内追加。
- [取消后仍可能多处理一帧] → 在每帧开始时检查取消事件，接受最多一帧的延迟，文档中写明。
- [任务只存在内存，重启丢失] → 明确非目标；前端在任务 404 时提示重新上传。
- [没有现成视频样例] → 交接文档标记为未验证，任务清单把样例获取放在实现之前；验收脚本对缺失样例失败而不是跳过。
- [标注视频编码增加复杂度和平台差异] → 首版不做，先交付 CSV 与单帧预览，后续再评估。

## Migration Plan

视频接口与页面模式均为新增，不修改现有图片接口、参数默认值和两张图片的验收判据。合并后若需回滚，删除视频相关路由、任务类和前端模式即可，图片功能不受影响；已归档的图片检测变更不需要迁移。
